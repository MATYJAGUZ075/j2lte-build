# FIX-0002 — Framebuffer console para capturar printk durante boot

## Problema
LOS20 queda en logo Samsung sin USB/adb y sin ningún log del kernel: pstore/last_kmsg vacíos, INFORM3 ilegible (MMIO), snapshot/sec_debug sobrescritos por TWRP, sin hardware UART.

## Evidencia
- `drivers/video/console/fbcon.c` presente; `VT=y`; fonts auto con fbcon (`FONT_8x16` default); `LOGO` off.
- DECON_FB probado (`dsim@14800000` en dmesg TWRP).
- `FRAMEBUFFER_CONSOLE_DETECT_PRIMARY` innecesario: un solo framebuffer (`decon_fb`, fb0); fbcon lo toma por defecto.

## Hipótesis
Con fbcon, el framebuffer muestra los `printk` en pantalla; lo último visible (foto) marca el punto de detención. Si la pantalla no cambia, el hang es anterior al probe de DECON (también informativo).

## Archivos modificados
- `kernel/samsung/exynos3475/arch/arm/configs/lineage-j2lte_defconfig:2491`

## Cambio
```
-# CONFIG_FRAMEBUFFER_CONSOLE is not set
+CONFIG_FRAMEBUFFER_CONSOLE=y
```
Una línea Kconfig. Sin código C, DTB, Binder, EXT4, USB, HALs, watchdog ni PANIC_TIMEOUT.

## Por qué
Único canal de log sin persistencia, hardware, MMIO ni reboot: la pantalla misma. Fonts (`FONT_8x16`) se activan solas por dependencia.

## Riesgos
Mínimos: consola extra sobre fb ya inicializado; no toca boot/init/particiones; reversible en 1 línea. Si el hang es pre-DECON, la pantalla quedará igual (dato útil, no regresión).

Pendiente: `mka bootimage` + flash BOOT + foto de pantalla tras 5 min.
